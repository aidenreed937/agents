# 面试卡：RAG 检索优化：混合检索（Hybrid Search）与重排（Rerank）

**模块**：05-agent-engineering ｜ **难度**：高级 ｜ **熟练度**：A

---

### 1. 30 秒电梯回答
生产级 RAG 检索的核心是**“BM25+向量双路召回 + Cross-Encoder 级联重排”的两阶段流水线**。
- **双路召回与无监督融合**：BM25 精确锁定专有名词/编号/错误码，向量检索覆盖语义泛化，两者通过 RRF（倒数排名融合）消除不同度量空间的打分失真；
- **交叉精排与上下文扩展**：对 Top 30~50 候选切块引入 Cross-Encoder 进行全注意力重排截断，配合 Small-to-Big 策略补充段落上下文，兼顾召回准确率与延迟。

---

### 2. 深入原理
1. **双路召回的互补性**：
   - **BM25 稀疏检索**：基于词频与逆文档频率，对人名、错误码、合同编号、精确条款具有极高的字面命中率。
   - **向量稠密检索**：基于 Embedding 模型的向量余弦距离，擅长同义表达改写、意图泛化与自然语言理解。
2. **多路融合算法：RRF（Reciprocal Rank Fusion）**：
   - 公式：$RRF(d) = \sum_{m \in M} \frac{1}{k + r_m(d)}$（常数 $k=60$），根据各路排名倒数累加综合分。
   - 优势：不依赖具体的绝对分数值，规避了 BM25 无界得分与向量余弦距离（0~1）分布不一致、难以直接线性相加的问题。
3. **重排机制（Bi-Encoder vs Cross-Encoder）**：
   - **Bi-Encoder（向量检索）**：分别独立编码 Query 与 Document 计算点积，速度快（毫秒级），但缺失两者之间的交互注意力。
   - **Cross-Encoder（如 BGE-Reranker）**：将 `[Query, Document]` 拼接后送入 Transformer 计算全交叉注意力，打分极准，但计算耗时大，因此仅对前 30~50 个候选切块做精排。

---

### 3. 工程取舍与边界
- **时延预算（TTFT 权衡）**：增加 Reranker 会给管线增加 80ms~250ms 延迟。对首字时延极度敏感的场景，可通过缩小初筛候选集（如仅重排 Top-15）或在独立 GPU 上托管推理服务优化。
- **Small-to-Big 上下文扩展**：切块阶段使用较小颗粒度（如 300 tokens）保证向量检索与重排的锐度；命中后通过元数据反查其父级段落或相邻切块拼接输入模型，兼顾检索精准度与模型上下文完整性。

---

### 4. 高频追问应对
- **追问 1：在 PostgreSQL 中如何一体化实现 BM25 和向量混合检索？**
  - **应对**：利用 PostgreSQL 原生全文检索（`tsvector` + `to_tsquery`）结合 `pgvector` 的 `<=>` 距离计算，单条 SQL 通过 CTE 并发查询两路，并用 SQL 窗口函数 `rank()` 计算 RRF 融合，避免引入额外的 Elasticsearch 实例。
- **追问 2：Cross-Encoder 的输出分数如果是负数或无界的，如何处理？**
  - **应对**：Cross-Encoder 原始输出通常是 Logits 实数。工程上不能用绝对阈值硬过滤，应仅用于相对排序；若需设定过滤阈值，应在后处理代码中通过 Sigmoid 函数（`1 / (1 + e^-x)`）归一化至 0~1 区间后再判定。
- **追问 3：如果检索出来的切块之间存在新旧制度冲突，如何防范？**
  - **应对**：切块元数据中记录版本号与生效日期，在 SQL 过滤或排序时按时效性提升新政策权重；同时在 Prompt 中约束“存在冲突时以最新生效日期为准，并指明旧版本差异”。
