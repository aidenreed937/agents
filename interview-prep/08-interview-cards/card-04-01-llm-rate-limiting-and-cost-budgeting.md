# 面试卡：高并发 LLM 网关限流（RPM/TPM）与任务调度系统设计

**模块**：04-system-design ｜ **难度**：高级 ｜ **熟练度**：B

---

### 1. 30 秒电梯回答
大模型上游供应商（如 OpenAI、Anthropic）施加的不是普通的 QPS 限制，而是双维度的 **RPM（Requests Per Minute）** 与 **TPM（Tokens Per Minute）** 严格硬限制。
架构设计必须将 LLM 调用从同步阻塞转为**“带配额感知的自适应漏桶/令牌桶网关”**：前端请求进入分布式优先级队列（按租户/VIP 分级），调度器依据实时剩余 Token 预算动态放行；同时结合**多模型供应商轮询路由（Fallback Routing）**、**语义缓存（Semantic Cache）**与**租户月度预算硬熔断**，确保系统在高并发冲击下不被供应商 429 打崩。

---

### 2. 深入原理
1. **双维度令牌桶（RPM + TPM Dual Token Bucket）**：
   - 传统网关只需统计请求次数（RPM）。而大模型中单次请求可能消耗 500 tokens，也可能消耗 50,000 tokens。
   - **预估与校准机制（Reserve & Settle）**：
     - 请求入队前：根据输入 prompt 长度预估总 token（输入 + 预估输出 max_tokens），从 Redis TPM 令牌桶中原子预扣（`Reserve`）；若配额不足则请求在队列中暂缓等待；
     - 请求完成后：根据上游实际返回的 `usage.total_tokens` 计算差额，返还多扣的配额或补扣（`Settle`）。
2. **分级排队调度（Priority Queue）**：
   - 使用 Redis Sorted Set（ZSET）或 RabbitMQ/Kafka 实现带权重的优先级队列。付费企业租户赋予高权重，免费或离线批处理任务赋予低权重。
3. **多模型自动熔断降级（Provider Fallback & Circuit Breaker）**：
   - 主模型通道（如 Claude 3.5 Sonnet / GPT-4o）触发 429（Rate Limit）或 5xx 错误时，熔断器打开，动态将流量透明降级路由至备用模型（如 DeepSeek V3、Gemini Pro 或本地 vLLM 私有化集群）。

---

### 3. 工程取舍与边界
- **精确预估 vs 吞吐量瓶颈**：由于模型实际生成的输出 Token 数在推理前无法精确预测，若 `Reserve` 预扣全部 `max_tokens`（例如 4096），会导致并发度被严重低估打满；若不预扣只后结算，瞬时并发会直接触发上游供应商的 429 报错封禁。折中方案是按“输入 Token + 历史平均输出 Token 的 P90 值”进行预扣，并保留 15% 的安全水位余量。
- **语义缓存（Semantic Caching）的边界**：对高相似度问题直接返回历史生成结果可大幅节省 Token 并降低延迟。但仅适用于事实类、只读类查询（如“公司报销流程是什么”），严禁用于携带用户动态上下文或具有创造性要求的任务。

### 4. 高频追问应对
- **追问 1：如果大模型上游返回了 HTTP 429，并且响应头带有 `retry-after: 23`，调度器应该怎么做？**
  - **应对**：不能让所有受阻协程各自 sleep 后同时重试（会引发下一次雷鸣般的并发冲击）。调度器网关应拦截 429 信号，将该供应商通道的全局状态置为“熔断等待 23s”，同时为后续请求启动“指数退避 + 全局随机抖动（Full Jitter）”，并自动将即时流量分流至预备的备用供应商。
- **追问 2：多租户场景下，单个大客户发起海量批量文档总结任务，把全系统的 TPM 耗尽导致其他普通用户瘫痪怎么防？**
  - **应对**：实施**多租户公平队列（Fair Queuing）与配额硬隔离**。每个租户分配独立的最大瞬时并发通道数与每小时 Token 上限；无论单个客户积压多少任务，其最大消费速率不得超过分配的租户配额（如不得超过系统总承载能力的 30%）。
- **追问 3：如何在大模型网关层实现月度成本防爆（Cost Guardrail）？**
  - **应对**：网关维护实时的租户财务计费账本。设定三级水位线：达到 80% 触发告警邮件；达到 100% 自动降级为低成本小模型；达到 120% 硬熔断阻断调用并向前端抛出提示，防止因循环调用或死循环产生天价账单。
